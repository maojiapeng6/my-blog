## 项目概述

把一台家用主机做成全家每天都在用的基础设施。从硬件选型、系统安装，到服务编排、网络打通与日常运维，全部独立完成。

## 硬件与系统

- **CPU**：Intel Core i5-14500（14 核 20 线程，带核显，承担影音硬件转码）
- **内存**：32 GB（十余个容器常驻后占用约 26 GB）
- **存储**：1 TB NVMe（系统与容器）+ 3.6 TB 机械盘（数据），存储池 754 GB，已用约 621 GB
- **系统**：FnOS（Debian 系），所有服务以 Docker Compose 编排，无一处使用图形化安装

## 跑着的服务

| 服务 | 作用 | 关键端口 |
| --- | --- | --- |
| Emby | 家庭影音中心，海报墙刮削 + 硬件转码 | 8096 |
| CloudDrive2 | 网盘挂载为本地目录，供影音库直接读取 | — |
| Cloudflared | Cloudflare Tunnel 内网穿透，外网免端口映射访问 | — |
| MediaTidy | 媒体文件自动改名与目录规范化 | 2019 / 8091 |
| 本地大模型 API | 提供本地推理接口 | 3001 |
| 资源工具 / 辅助服务 | 资源处理、反爬代理等 | — |

## 我做了什么

- **服务编排**：十余个容器全部使用 Docker Compose 管理，一个服务一个目录，配置可备份、可迁移、可版本化
- **端口治理**：建立端口分配记录，容器端口与对外暴露端口分离，避免冲突
- **资源规划**：根据实测内存占用（26 GB）确定容量边界，配置日志上限防止磁盘被吃满
- **影音链路**：文件进入 → 自动整理 → 刮削识别 → 多端播放，全链路自动化
- **外网访问**：通过 Cloudflare Tunnel 打通，不在路由器上开端口
- **容错**：构建与部署脚本采用"失败保留上一版"策略，避免单次失败导致服务中断

## 遇到的典型问题

- 精简镜像缺少构建依赖（如 git）导致容器内安装卡在国外源 → 改用完整镜像
- 容器内 DNS 解析慢导致构建阶段外部资源下载超时 → 为容器指定国内 DNS
- 静态资源目录层级写错导致线上 404 → 明确区分源码目录与静态资源目录
- 下载类服务未限速影响家庭网络 → 增加限速策略

## 收获

这个项目让我完整走了一遍"从硬件到服务"的全流程：容量规划、服务编排、网络打通、自动化与容错。它现在稳定服务全家，维护成本接近于零——这是我判断一个系统是否做对了的主要标准。
